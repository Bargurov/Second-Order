# יומן פיילוט FOMC

היומן בנוי משני חלקים, ואין צורך בדף באפליקציה:

1. **מה קרה בפועל** נקבע אוטומטית מתוך המסד, בקריאה בלבד:
   ```
   python -m second_order pilot-ledger --table
   ```
   הפקודה מציגה לכל אחד משמונת המועדים את המצב, את מזהה המקרה, את מספר הגרסאות הנוספות, את התוויות (שנתיים ועשר
   שנים) ואת הסיבה.
2. **סיבות שרק אתם יודעים** נרשמות ביד בקובץ `content/pilot/fomc-pilot.json`, ליד התאריך:
   - `not_held`: ההודעה לא התקיימה, למשל ישיבה שבוטלה.
   - `missed_reason`: ההודעה התקיימה ולא הוקפאה, למשל "פרסום H.15 התעכב" או "לא הספקתי עד 07:00".
   - `note`: הערה חופשית, למשל תאריך שהוזז ומה היה התאריך הקודם.

   אחרי כל שינוי מבצעים קומיט. הפקודה מציגה את הסיבות האלה בעמודת Reason.

## כלל הספירה

- **מקרה אחד לכל הודעה:** ההקפאה הראשונה. גרסאות נוספות (כיוון אחר, אופק אחר או נוסח אחר) נשמרות ומוצגות, אבל לא
  מוסיפות מקרה ולא מחליפות את הראשון.
- **הערכה של גרסה נוספת** מוצגת, אבל לא נספרת.
- **הקפאה ראשונה שאינה לפי הכללים** (תאריך פרסום אחר, או הקפאה אחרי חצות בניו יורק) הופכת את ההודעה להחמצה, וגרסה
  מאוחרת לא מתקנת אותה.
- **הקפאה ראשונה שאינה תואמת את הרגליים הקבועות** היא `nonconforming`. מה נבדק:
  - חייבות להיות בדיוק שתי רגליים: שנתיים (`yield:ust2y_cmt_h15`) כרגל ראשית, ועשר שנים (`yield:ust10y_cmt_h15`)
    כרגל משנית, שתיהן באופק 5.
  - הזיהוי נעשה לפי המזהים האלה ולא רק לפי סימון ה-primary ברשומה. לכן רגל ראשית מוחלפת, רגל חסרה או נוספת, או
    אופק אחר, כולם הופכים את המקרה ללא תואם.
  - המקרה נשאר המקרה של ההודעה: הוא נספר כמוקפא, ומוצג עם הסיבה ועם ההערכה שלו אם יש.
  - הוא לא נכנס לסיכום התוצאות התקינות.
  - גרסה תקינה מאוחרת לא מחליפה אותו.
- **story ID שגוי** בתאריך של הודעה מופיע תחת Unmatched, ואינו נספר.
- **לפני חותמת ההתחלה** שום הודעה לא נספרת, גם אם יש במסד הקפאות מתרגול. חותמת ההתחלה היא רגע מדויק ב-UTC, לפני
  14:00 שעון ניו יורק ב-9.12.2026. זמן הפרסום שבהקפאה מושווה אליה כרגע מדויק, כולל אזורי זמן, ולא רק לפי התאריך.
  מקרה שפורסם לפניה נרשם `before_start` ולא נכלל בדיעבד.
- **לא מתרגלים במסד הפעיל עם story ID אמיתי** (למשל `fomc-2026-12-09`). הקפאה כזאת תהיה "הראשונה" של ההודעה.

## המצבים

| מצב | משמעות |
| --- | --- |
| `not_started` | לפרוטוקול עדיין אין חותמת התחלה |
| `before_start` | זמן הפרסום (או הזמן הצפוי, 14:00 בניו יורק) קודם לחותמת ההתחלה |
| `scheduled` | מתוכנן, ועדיין לא הגיע |
| `open` | חלון ההקפאה פתוח היום (לפי התאריך בניו יורק) |
| `pending` | הוקפא, וממתין לתוצאה ולהערכה |
| `assessed` | הוערך, לפי ההערכה הראשונה של המקרה, ונכנס לסיכום |
| `nonconforming` | הוקפא, אבל לא לפי הרגליים הקבועות. מוצג עם הסיבה ולא נכנס לסיכום |
| `missed` | הוחמץ, עם סיבה |
| `not_held` | ההודעה לא התקיימה, עם סיבה |
